# 🐺 AI 狼人杀

> 12 名 AI 智能体在信息不对称约束下进行协作、对抗与博弈的经典狼人杀对局。

12 个 AI 玩家（每个角色由 LLM 驱动），遵循经典 12 人屠城局规则，通过三通道通信（公开发言、狼人私聊、神职行动）进行推理、伪装、博弈。纯观战模式，不限时，完整展示所有 AI 的内心独白与决策过程。

## 核心设计

### 1. 通信三通道

游戏设计了三个完全隔离的信息通道，严格遵守信息不对称规则：

| 通道 | 参与者 | 内容 |
|------|--------|------|
| **公开发言** | 所有人可见 | 日间发言、讨论、投票 |
| **狼人私聊** | 仅狼人可见 | 夜间狼人团队商议策略 |
| **神职行动** | 仅神职本人 + GM | 预言家查验、女巫救/毒、守卫守护 |

每个 agent 只知道允许它知道的信息，不越权传递。

### 2. Agent 架构

每个玩家都是一个独立的 `AgentBase` 实例，拥有完整的记忆和推理系统：

```
AgentInstance
├── build_system_prompt()   → 加载对应角色的 prompt 模板
├── reflect()               → 分析局势 → 制定策略 → 内心独白 → 做出决定
├── speak()                 → 公开发言（基于 reflect 结果）
├── discuss()               → 白天讨论环节回应他人
├── vote()                  → 投票决策（结构化 JSON 输出）
├── night_action()          → 夜间行动（各角色不同）
├── wolf_chat()             → 狼人私聊频道
└── on_phase_change()       → 感知阶段变化
```

### 3. 记忆系统

每个 agent 维护独立的 `AgentMemory`，包含：

- **belief state（身份推测）** — 对每个存活玩家身份的猜测及置信度
- **发言历史** — 公开发言和内心独白的完整记录
- **私人信息** — 例如预言家的查验结果、女巫的用毒状态
- **summarization（摘要）** — 早期轮次的发言自动摘要压缩，避免超长上下文

### 4. Reflection（反思机制）

每次发言前，agent 先进行四步反思：

1. **局势分析** — 当前场上形势、死亡信息、发言疑点
2. **策略** — 根据角色身份制定发言策略
3. **内心独白** — 真实想法（仅观战者可见，不公开）
4. **决定** — 最终发言内容

反思后还会自动更新 belief state，形成对其他玩家的判断。

### 5. 投票与决策结构化输出

所有角色行动（投票、狼人击杀、女巫用毒、守卫守护等）均要求 agent 以 **JSON 格式** 输出，确保了决策的可解析性和一致性。

## 游戏流程

```
                    ┌──────────┐
                    │ 游戏开始  │
                    └────┬─────┘
                         ▼
              ┌─────────────────┐
              │   夜间阶段     │
              │ 狼人击杀商议    │
              │ 狼人投票选目标  │
              │ 预言家查验      │
              │ 女巫救/毒       │
              │ 守卫守护        │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  处理夜间结果   │
              │  (死亡/被救)    │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  白天阶段       │
              │ 天亮公告（昨晚死者）│
              │ 每人轮流发言    │
              │ 自由讨论（随机半数）│
              │ 投票放逐        │
              │ 猎人开枪（如适用）│
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  检查胜负       │
              │ 狼人全灭→好人胜 │
              │ 村民全灭→狼人胜 │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │ 继续/结束       │
              └─────────────────┘
```

### 详细阶段

| 阶段 | 说明 |
|------|------|
| **狼人行动** | 狼人私聊商议，投票选击杀目标（多数决） |
| **预言家行动** | 查验一名玩家，得知其阵营（好人/狼人） |
| **女巫行动** | 得知被刀玩家，决定是否用解药/毒药（首晚必救设置） |
| **守卫行动** | 守护一名玩家（不能连续两晚守同一人） |
| **天亮公告** | 通报夜间死亡名单（含死亡原因） |
| **白天发言** | 按顺序每人发言一次（首日随机，后续从上轮出局者开始） |
| **自由讨论** | 随机抽取半数存活玩家，对他人发言进行回应、质疑、辩护 |
| **投票放逐** | 全员投票，平票则重新投票一次 |
| **猎人开枪** | 被放逐或被狼杀的猎人可选择带走一人 |

## 角色与 Prompt

项目包含 7 个角色，每个角色有独立的 prompt 文本文件：

### 狼人（Werewolf）
- **阵营：** 狼人
- **能力：** 每晚和队友商议击杀一人
- **设计重点：** 双重思维（真实策略 + 对外伪装），统一口径防暴露，利用假信息误导好人

### 预言家（Seer）
- **阵营：** 好人
- **能力：** 每晚查验一人阵营
- **设计重点：** 不要过早暴露身份，用怀疑语气引导投票，适度分享线索

### 女巫（Witch）
- **阵营：** 好人
- **能力：** 一瓶解药（首晚必救）+ 一瓶毒药
- **设计重点：** 首晚必须使用解药，毒药看准再投，保护自己不被票出

### 猎人（Hunter）
- **阵营：** 好人
- **能力：** 死亡时带走一人（毒杀除外）
- **设计重点：** 留遗言指出怀疑对象

### 守卫（Guard）
- **阵营：** 好人
- **能力：** 每晚守护一人（不能连守同一人）
- **设计重点：** 关注女巫用救情况，智能选择守护目标

### 村民（Villager）
- **阵营：** 好人
- **能力：** 投票权
- **设计重点：** 站边分析、怀疑列表、注意发言矛盾

## 评估框架

`evaluate.py` 是内置的批量评测工具，可自动运行多局游戏并统计关键指标。

### 使用方法

```bash
cd /home/ubuntu/ai-werewolf
source venv/bin/activate

# 跑 3 局，显示详细日志
python evaluate.py --games 3 --verbose

# 跑 5 局，同时输出 JSON 原始数据
python evaluate.py --games 5 --json

# 快速跑 1 局
python evaluate.py --games 1
```

### 输出指标

| 指标 | 说明 |
|------|------|
| 好人/狼人胜率 | 阵营胜负统计 |
| 游戏轮数 | 平均每局持续轮数 |
| 好人投票命中率 | 好人投给狼人的比例 |
| 狼人平均存活轮数 | 狼人存活时长 |
| 狼人击杀神职数 | 狼人击杀特殊角色的效率 |
| 预言家查验准确率 | 预言家判断正确率 |
| 女巫用救/用毒 | 女巫是否使用了解药和毒药 |

## 前端界面

Vue 3 前端提供实时观战界面，深色主题（青绿/翠绿/暖金配色）：

- **三栏布局**：玩家列表 | 事件时间线 | 统计数据
- **实时 WebSocket**：推送所有游戏事件
- **内心独白展示**：每个 AI 的真实想法
- **死亡历史**：按轮次展示淘汰记录
- **存活统计**：双方存活人数实时更新

### 启动方式

```bash
# 后端（开发模式）
cd /home/ubuntu/ai-werewolf
source venv/bin/activate
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload

# 前端（开发模式，另一个终端）
cd /home/ubuntu/ai-werewolf/frontend
npx vite --host 0.0.0.0
```

前端已构建完成（`frontend/dist/`），可直接部署到静态服务器。

## 快速启动

```bash
# 1. 克隆仓库
cd /home/ubuntu/ai-werewolf

# 2. 创建虚拟环境
python3 -m venv venv
source venv/bin/activate

# 3. 安装依赖
pip install -r backend/requirements.txt

# 4. 配置 API Key（DeepSeek）
export DEEPSEEK_API_KEY="你的key"

# 5. 跑一局游戏
python3 -c "
import asyncio, sys; sys.path.insert(0, '.')
from backend.game.gm import GameMaster
from backend.game.models import GameConfig
async def run():
    gm = GameMaster(GameConfig(time_limit_enabled=False))
    gm.init_game()
    roles = [(p.id, p.role.value) for p in gm.state.players]
    print(f'角色分配: {roles}')
    await gm.run_game()
    print(f'获胜方: {gm.state.winner}, 轮数: {gm.state.round}')
asyncio.run(run())
"

# 6. 或使用评测框架
python evaluate.py --games 3 --verbose
```

## 开发历程

### 第一阶段：核心架构搭建

- 设计 12 人经典局模型（`Role`、`Camp`、`Phase` 枚举，`Player`、`GameState` 数据类）
- 实现 Game Master 状态机，严格按轮次推进（第一夜 → 白天 → 投票 → 放逐 → 后续夜 → ...）
- 实现 Agent 基础架构（`AgentBase`），每个玩家独立 agent 实例
- 设计通信三通道：公开发言、狼人私聊、神职行动
- 实现记忆系统（`AgentMemory`）：belief state（身份推测）+ 发言历史 + summarization

### 第二阶段：Prompt 工程迭代

- **死代码清理** — 将内嵌的 system prompt 提取为独立的 `prompts/*.txt` 文件
- **狼人欺骗强化** — 加入"双重思维"策略（真实战略 vs 对外人设）、伪装一致性要求
- **女巫修复** — 首晚必救从 0% → 100%（明确指令"你有一瓶解药和一瓶毒药"）
- **预言家优化** — 加入"不要过早暴露身份"、"用怀疑语气引导"策略
- **村民优化** — 加入"站边分析"、"列出怀疑列表"策略
- **狼人伪装优化** — 更强的"伪装好人身份"、"统一口径"要求

### 第三阶段：Bug 修复与稳定化

- **相位混淆修复** — 白天发言不再混入夜间决策内容
- **结构化输出修复** — 所有投票/技能目标改用 JSON 格式输出
- **Agent 存活状态同步修复** — GM 正确调用 `set_alive_players`
- **SOXKS 代理问题** — 通过清除系统代理环境变量解决 `httpx` 代理冲突
- **女巫数据采集去重** — `NightAction.round` 字段补全，投票数据去重

### 第四阶段：评测框架

- 创建 `evaluate.py`，支持 `--games N` 批量评测、`--verbose` 详细输出、`--json` 原始数据导出
- 采集指标：胜负、轮数、死亡时间线、好人投票命中率、狼人击杀神职数、预言家准确率、女巫/守卫行动

### 第五阶段：讨论环节

- 增加 `DAY_DISCUSSION` 阶段，白天每人发言后随机抽半数玩家进行辩论回应
- 讨论内容包含：质疑发言矛盾、为自己辩护、支持认为的好人、追问信息
- 效果显著：投票命中率从 ~19% 提升，首次实现好人胜利
